# LingXia 0.25.1

Packaging identity comes only from what a project declares: MSIX takes its
Identity, publisher name and Store identity name from `lingxia.yaml`, Windows
installers and executables name the publisher, and Harmony's `vendor` comes from
`harmony.vendor`. Nothing is derived from the product name or a scaffold
placeholder any more. Installed Windows apps keep their data under the app id,
so renaming the product keeps it. `lingxia install` fails where it cannot
install, and installs every iOS input it accepts. Pages no longer lose their
initial Logic state when a WebView becomes ready before the page registers.

## Breaking changes

### MSIX requires `windows.publisher`

- Building an MSIX without `windows.publisher` now fails instead of using
  `CN=<productName>`. Set it to Partner Center's Package/Identity/Publisher for
  the Microsoft Store, or to the signing certificate's subject. A
  `--format msix --self-signed` local test package still builds without it,
  as `CN=LingXia Local Test`.

### `lingxia install` fails where it cannot install

- On macOS and Windows, `lingxia install` used to print that apps run directly
  and exit 0 without installing anything. It now fails and says what to open
  instead: the `.app`/`.dmg`, or the Windows installer or `.exe`.
- An Android `.aab` fails before adb, asking for the `.apk`.

## Microsoft Store identity

- `windows.publisherDisplayName` sets MSIX `PublisherDisplayName`, which the
  Store requires to equal the Partner Center publisher display name. Without
  it, the name is the `O=` (else `CN=`) of `windows.publisher`, never the
  product name.
- `windows.store.identityName` sets the MSIX Identity Name to Partner Center's
  Package/Identity/Name. It changes only the MSIX: the NSIS install directory,
  uninstall key, update feed and taskbar identity keep `windows.appId`, so
  existing installs still upgrade in place.

```yaml
windows:
  publisher: "CN=00000000-0000-0000-0000-000000000000"
  publisherDisplayName: "Contoso"
  store:
    appId: "9NXXXXXXXXXX"
    identityName: "12345Contoso.ContosoApp"
```

## Windows

- Installed apps keep their data under `%LOCALAPPDATA%\<windowsAppId>` instead
  of `%LOCALAPPDATA%\<productName>`, matching portable mode and the
  Apple, Android and Harmony sandboxes, so renaming the product no longer
  strands data. On first start, state an earlier version left at the
  product-name folder moves once, only when that folder holds LingXia's app
  registry; if it cannot move, it stays in use. Apps without an explicit
  `windowsAppId` keep the per-product folder.
- The NSIS uninstall entry shows the publisher, and the executable's version
  resource carries it as `CompanyName`. Both stay empty when no publisher is
  declared.

## Harmony

- `harmony.vendor` is written to `AppScope/app.json5` `vendor` at build time.
  Without it, `vendor` is emptied rather than left at a placeholder; new
  projects no longer start with `"vendor": "example"`.

## iOS install

- `lingxia install -a` accepts an `.ipa`, a `.app`, or a `lingxia package`
  `dist/ios` directory. Each previously failed: an `.ipa` was read as a bundle
  directory, and a `.app` was taken for a package directory.
- Install signs a temporary copy, so device signing no longer rewrites the
  build output or the packaged app. It prints the package (platform, version,
  env) and the signed app (name, version, bundle id) it installs, and
  `lingxia dev` takes the bundle id from the install.

## Pages

- An immediately ready WebView could send `CreatePage` before its page was
  registered; the page then recovered without its Logic service and showed no
  initial state. Pages now register before native setup starts, for regular,
  navigation-entry and isolated pages, and only the winner of concurrent route
  candidates starts.
- A page whose initial setup fails is removed and its hosting surface closed,
  reporting `Failed`; a page disposed before setup completes still reports
  `Gone`. Headless pages complete setup through the same readiness path, so a
  failed document reload keeps the live service.
