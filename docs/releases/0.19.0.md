# LingXia 0.19.0

This release expands app testing around a running `lingxia dev` session: page
contracts, isolated profiles, Logic network routes, mock handlers, scenarios,
a test clock, and clearer failure reports. It also changes the View hooks and
several test and CLI APIs. Upgrade the runtime, CLI, `@lingxia/types`, View
packages, and `@lingxia/test` together; a mismatched development host or
Runner now fails the version check with a suggested fix.

## Breaking changes

### Page Views and actions

- React and Vue pages use `useLxPage<Data, Actions>()` for `{ data, actions }`
  and `useLxHost()` for host facts such as `sizeClass`, `aside`,
  `displayLanguage`, `formFactor`, `os`, and `runner`. Replace
  `useDisplayLanguage`, `usePlatform`, `useSurfaceContext`, and
  `useLxPageChrome`; page chrome is exposed through `--lx-page-chrome-*` CSS
  variables. HTML pages use `pageReady`, `getPage`, `subscribePage`, `getHost`,
  and `subscribeHost`. A page with Logic mounts after its first state arrives.
- View data is deeply readonly and frozen in development. Send changes through
  page actions; type helpers that accept data with readonly properties and
  arrays. A typed action takes at most one JSON payload, and plain objects
  containing `type` and `detail` are passed through as data. Streamed actions
  are typed as streams on the View side.
- `LxMediaSwiper` callbacks receive the payload directly, such as
  `onChange={({ index }) => ...}`. Remove `pageBindings` from `LxPicker`,
  `LxVideo`, and `LxMediaSwiper`. Stream/channel options take the method type,
  for example `LxStreamOptions<typeof actions.feed>`; supply `params` for a
  required payload and `initial` for a reducer.
- A page's `this.signal` is aborted just before `onUnload`. Pass it to work
  started by that page, such as `fetch(url, { signal: this.signal })`. The
  signal also aborts on retirement without `onUnload`; it does not fire when
  the whole lxapp shuts down. `signal` is a reserved Page config key.

### Test fixture and assertions

- Bind a page with `const page = await t.app.page<Contract>({ name })` and use
  `page.data()`, `page.actions.method(payload)`, or `page.view.testId(id)`.
  The handle stays on that instance and rejects after it closes or is replaced.
  `t.app.view` follows the current page; `t.app.logic.eval(fn, ...args)` reads
  Logic. Replace the old `t.app.page` raw driver methods, `t.app.eval`,
  `t.app.pageData`, `t.app.callPage`, and `logic.call` accordingly. A page
  action with a custom timeout uses `page.invoke(method, { payload, timeout })`.
- Use `expect(locator)` for a retrying locator assertion,
  `expect.poll(read)` for a retrying value, and `expect(value)` for one check.
  `t.expect` is removed. `expect(fn)` supports `toThrow` only, and every
  `expect` needs a matcher. Await fixture calls before the spec returns;
  unfinished calls now fail that spec. `toEqual` matches Set/Map object
  members one-to-one.
- Use `t.arg('key')`, optionally with `{ default }` or
  `{ required: false }`, instead of `t.args`. `t.profile` moves to
  `t.app.profile`; `t.apps.lxapp(id)` becomes `t.automation.lxapp(id)`.
  A spec has no global `lx`; use `t.automation` or import `rawAutomation`
  from `@lingxia/test/runner` for setup outside a spec. Runner exports and
  report types move to `@lingxia/test/runner` and `@lingxia/test/report`.
- `logic.eval` and `view.eval` take typed functions and JSON arguments/results;
  pass captured values as arguments. A result such as a DOM node, Date, Map,
  or function must be converted to JSON first. Eval options such as
  `{ timeout }` come before the function. `t.waitFor(read, { until, timeout })`
  replaces the old positional acceptance callback. Fixture timeouts have
  `E_TIMEOUT`; the underlying driver code remains in the cause.
- Fixture navigation waits for the landed page's `onReady` by default. Pass
  `waitUntil: 'commit'` for page-stack completion, and use `timeout` rather
  than `timeoutMs`. Locator visibility means rendered, even below the fold:
  use `toBeInViewport()` or `waitFor({ state: 'inViewport' })` for placement.
  Locator actions take `{ timeout, force }`, without `interval`; route handles
  use `remove()`.
- A timed-out spec has its remaining work revoked and the run stops with later
  specs marked not run. A failed spec records its action, page instance,
  network calls, and recovery information; run-level cleanup failures appear
  in `run_errors` and fail the run. Custom codes used by `t.reject` or
  `spec.fail` must be declared through `AppErrorCodes`; a code not in
  `TestErrorCode` is rejected by the types.

### CLI and automation

- Start a session with `lingxia dev --background`, run `lxdev test`, and stop
  it with `lingxia dev stop`. `lingxia test` and `lingxia dev status` are
  removed; use `lxdev session` to list sessions. `lxdev app` is now
  `lxdev host`, and `lingxia runner set|clear` moves under `lingxia auth
  runner`. `lxdev test --format json|jsonl` replaces `--json` and `--jsonl`;
  use `--pass-with-no-tests` instead of `--allow-no-tests`.
- `lxdev lxapp page` takes positional operands: `page click SELECTOR`,
  `page fill SELECTOR TEXT`, or `page press KEY [SELECTOR]`; remove
  `--css`, `--text`, and `--key`. Automation objects returned to JavaScript
  use camelCase (`appId`, `currentPage`, `inViewport`, `rect.centerX`);
  `lxdev --json` keeps its wire field names. Raw page waits use `attached`
  and `detached` instead of `exists` and `gone`.
- `lingxia dev` uses a Runner from the same build; local CLI builds need a
  matching locally built Runner. The Runner capsule follows the host: hidden
  on the host's home lxapp, shown on other lxapps. Remove
  `lxdev runner set --capsule` and the `capsule` device setting.
- `lingxia publish` uses the v2 package API. A host package must have
  `lingxiaId` in its packaged `app.json`; the `--lingxia-id` flag and v1
  upload route are removed.

## Testing and development

- `t.app.network.route()` answers Logic `fetch` and `Rong.SSE` with a response,
  abort, passthrough with `patchJson`, hang, sequence, or SSE stream. Routes
  are per spec; their handles expose `calls()` and `waitForCall()`. Request
  records carry a monotonic `seq` so a wait reports a trimmed log gap.
- `mocks/index.ts` holds reusable HTTP and Worker Function handlers. Set a
  session default in `mocks/config.json`, choose `--mock all|none` when
  starting `lingxia dev`, or switch the live selection with `lxdev mock`.
  `lxdev mock use NAME[:VARIANT]` applies a scenario file; `t.scenario.use`
  applies one inside a spec. Scenario files use one `rules` list with `http`
  and `function` rules. Saving `mocks/` reloads handlers; builds reject
  product imports from it.
- `lxdev test --profile empty|NAME|PATH` uses a throwaway app data profile;
  `--profile-save` writes a snapshot after a passing run. `restoreProfile`
  and `t.app.profile` can roll back per spec, with `{ keep: ['auth.*'] }`
  to preserve selected storage keys. `t.app.clock` controls Logic time;
  `t.app.dialogs` records toasts and dialogs and can queue one answer.
- Specs can be selected by directory, file, or `FILE:LINE`; `--list` works
  without a session. `lxdev.json` presets, tags, coverage manifests, OpenAPI
  response checks, and `--record-network` support repeatable suites. The
  default run budget scales with the selected suite, and `--shuffle` and
  `--repeat-each` help find order dependence. Secret args and secrets files
  are redacted from reports and rerun hints.
- `lingxia skill install` installs the agent skill. `lxdev host focus`
  raises the host window, and test runs raise it when they start. Long runs
  keep their session through quiet socket reads and reconnects; a locked
  macOS screen stops the run with one diagnostic.

## Runtime and hosts

- `reLaunch` unloads cached tab pages and opens a fresh target page. Closed
  Logic contexts are released. Bridge channels and streams settle once, and
  the first messages on a new channel are preserved.
- macOS and Windows fit the first window to the screen and remember its frame
  and maximized state. Windows gains NSIS, portable EXE, MSIX, and ZIP
  distributions, DPI-aware shell chrome, localized installer names, and a
  Downloads default for browser files. Store-channel hosts use the update
  feed as a version signal; direct updates still verify signatures.
- A Control app can switch the service environment of a production build
  with `lx.host.getServiceEnv()` and `lx.host.toggleServiceEnv()`; the next
  launch uses the selected environment.

## Dependencies

`redb` is 4.3.0. The resolved Rong set includes `rong` 0.6.3,
`rong_abort` 0.6.2, `rong_http` 0.6.3, and `rong_timer` 0.6.1. These carry
page-signal GC safety, working timer callbacks, and JavaScriptCore worker
GC timers. Both workspace and showcase lockfiles retain the newer Rong
versions; the manifest requires the abort and HTTP minimums so a lockfile
refresh cannot regress them.
