# LingXia 0.19.0

0.19.0 is mostly about `lxdev test` and `@lingxia/test`: specs can fake the
app's network, run on an isolated data profile that never touches your own app
data, read app Logic through typed functions, and get stable error codes when
something fails. Long runs no longer drop their session. Desktop hosts open a
better-sized first window and remember it, and Windows gains installer and
portable distributions.

Upgrade the runtime, the CLI, `@lingxia/types` and `@lingxia/test` together.

## Breaking changes

### Locator visibility means rendered, not in the viewport

A locator is visible when it is rendered (non-empty box, not `display:none`,
`visibility:hidden` or `opacity:0`), wherever it is scrolled. `toBeHidden()`,
`not.toBeVisible()` and `page.waitFor({ state: 'hidden' })` now fail for
content that is rendered below the fold or inside an overflowing sheet. Assert
viewport placement explicitly with `toBeInViewport()` or
`waitFor({ state: 'inViewport' })`; raw page queries report the old reading as
`in_viewport`.

### `lingxia publish` uses the v2 package API

`lingxia publish` uploads host packages to
`POST /api/v2/lingxia/{lingxiaId}/package?platform=` and lxapp/plugin packages
to `POST /api/v2/lxapp/{appId}/package?channel=`. The `--lingxia-id` flag and
the v1 upload route are removed. A host package must carry `lingxiaId` in its
packaged `app.json`, or publishing fails.

### Fixture navigation waits for the landed page

`t.app.nav.*` now waits until the landed page's `onReady` (`waitUntil:
'ready'`) unless the spec passes `waitUntil`. Pass `waitUntil: 'commit'` to keep
the old "page stack changed" resolution. `PageInfo.ready` now always means
"`onReady` was dispatched"; the WebView state moved to `webviewAttached`.

### `t.args` values may be `undefined`

`t.args` is typed `Readonly<Record<string, string | undefined>>`. Specs that
read `t.args.key` as a `string` need `t.arg('key')` (which throws naming the
missing `--arg`, or takes `{ required, default }`) or an explicit check. Run
controls (`grep`, `id`, `ids`, `shard`, `retries`, …) are no longer part of
`t.args`, so `--arg id=…` no longer filters the run; they are reported as
`meta.run`.

### Logic-side `lx.automation()` is typed narrower

In app Logic, `lx.automation().lxapp()` is typed `LogicLxAppDriver`: no
`network`, no nav `waitUntil: 'ready'`, no `captureCalls` — these reject in
Logic. Test programs get the full `HostRunAutomation` from
`@lingxia/types/automation-test-globals`. Imported `LxAppDriver` / `NavDriver`
types are unchanged.

### Generated spec ids are numbered per file

A spec without an id or ASCII slug gets `<file>-<n>` counted within its own
file, so adding a spec elsewhere no longer renames it. Suites with several
files may see generated ids renumbered once; update saved `--id` selections.

## New in testing

### Network routes for app Logic fetch

`t.app.network.route(pattern, handler)` fakes the app's Logic `fetch`, scoped to
the running spec and cleared when it ends. A handler is exactly one of:

- fulfill — `{ status?, statusText?, headers?, contentType?, delay?, body | json }`
  (`body` is a string, `ArrayBuffer` or `Uint8Array`; `delay` up to 30 s);
- `{ abort: 'failed' }` — fail like a transport error;
- `{ continue: true }` — pass through, optionally with `patchJson` to
  merge-patch the real JSON response;
- `{ hang: true }` — leave the request pending until the spec ends, for
  loading and timeout states.

`t.app.network.requests()` lists what the spec's routes saw, including
headers and body (text, cut to 64 KiB, with `bodyTruncated`). Routes appear in
the trace.

### Isolated test profiles

- `lxdev test --isolate` runs the app on an empty isolated data profile, so a
  suite never writes into your own app data.
- `--state NAME|PATH` seeds that profile from a saved snapshot, and
  `--save-state NAME|PATH` saves it after a passing run (`--save-state-on always`
  to save regardless); both imply `--isolate`. `--state auth --save-state auth`
  reuses a sign-in snapshot and refreshes it. Named snapshots live under
  `~/.lingxia/test-state/` with owner-only permissions.
- `spec(..., { restoreProfile: true })` checkpoints the isolated data before the
  spec and rolls it back afterwards. `t.profile` (also `t.app.profile`) exposes
  `checkpoint` / `restore` / `drop`. A rollback restores everything the app
  stored, sign-in tokens included, so keep checkpoints short-lived if the app
  rotates single-use refresh tokens.
- Host automation can do the same through
  `lx.automation().lxapp().profile.checkpoint()`, `restore(id)` and `drop(id)`.
  Outside an isolated run these reject with `E_PROFILE_NOT_ISOLATED`.
- lxdev refuses isolation against a host that does not report support for it,
  rather than silently running on real data.

### Typed access to app Logic

- `t.app.eval(fn, ...args)` runs a function in Logic with a typed
  `{ lx, getApp, getCurrentPages }` scope and JSON arguments, resolving to its
  typed result; `t.app.page.eval(fn, ...args)` does the same in the WebView.
  The `{ script }` forms are unchanged.
- `t.app.pageData<T>()` and `t.app.callPage<R>(method, ...args)` wrap it.
- `t.waitFor(read, accept?, { timeout, interval, retryIf })` polls and resolves
  to the accepted value.

### Stable error codes and failure diagnostics

- Driver rejections carry stable codes: `E_AUTOMATION_PRIVILEGE`,
  `E_PAGE_NOT_ACTIVE`, `E_PAGE_NOT_READY`, `E_ELEMENT_NOT_FOUND`,
  `E_ELEMENT_NOT_INTERACTABLE`, `E_AUTOMATION_TIMEOUT`, `E_EVAL_SCRIPT`,
  `E_EVAL_TIMEOUT` (fallback `E_AUTOMATION`), exported as
  `AUTOMATION_ERROR_CODES` from `@lingxia/types/automation`. Messages are
  unchanged.
- `PageInfo` reports an `instanceId`, so a page the app replaced is
  distinguishable from the one the spec navigated to.
- A failed spec records the action that failed and the page instance it failed
  on; `report.json` adds a flat `failures[]`, and lxdev prints e.g.
  `failed at page.click [data-testid=save] on page "devices" (#a1b2) — E_PAGE_NOT_ACTIVE`.
- `spec.fail(title, { expected: { code, message } }, body)` can pin the expected
  code; any other body failure is graded `failed`.

### Run scaling, shuffling and repeats

- Without `--timeout-secs`, the run budget scales with the suite:
  max(300 s, 30 s per planned spec), capped at 3600 s. When it runs out, the
  remaining specs are reported as not run and lxdev prints "run budget
  exhausted after N/M specs".
- `--shuffle[=SEED]` runs the selection in a reproducible random order.
- `--repeat-each N` runs every spec N times, each as its own case, to expose
  flakiness.

### Secret args

`--secret-arg KEY=VALUE` values are masked as `***` everywhere: reports
(JSON/HTML/JUnit), events, `t.attach` payloads, forensics attachments and rerun
hints. Credential-named `--arg` keys (`authToken`, `DB_PASSWORD`, `apiKey`, …)
are masked in `meta.args`. `t.args` keeps the real values.

### More spec APIs

- `t.skip(reason)` skips a case from inside its body.
- Locator matchers `toContainText(text | RegExp)` and
  `toHaveAttribute(name, value?)`.
- `locator.waitFor({ state })` accepts `attached` and `inViewport`;
  `locator.filter({ hasText })`, `.first()` and `.last()` narrow matches.
- `click({ force })` / `fill(text, { force })` act on elements no scroll can
  reach.
- `spec.fail` grades any body failure (not only a failed assertion) as `xfail`.

### lxdev run control

- `lxdev test --cancel-active` cancels a run left holding the session by a
  client that died, and shows its id, age and last poll. It refuses a run a
  live client polled in the last 15 seconds. The runtime also cancels a run
  nobody has polled for 180 s.
- `lingxia --version` and `lxdev --version` print the build commit and a dirty
  flag, e.g. `0.19.0 (1a2b3c4d5 2026-09-23)`.

## New for apps and hosts

- A prod build can switch its service environment with
  `lx.host.getServiceEnv()` and `lx.host.toggleServiceEnv()` (Control app only);
  the next launch uses that environment and shows a `DEV` mark while on dev.
- Windows: `lingxia package -p windows` builds a per-user NSIS installer by
  default, with portable EXE, MSIX and ZIP as options, format-aware updates and
  Authenticode signing hooks.
- Store-channel hosts treat the update feed as a version-only signal and may be
  built without trusted keys; direct updates still verify downloads and
  signatures.

## Fixes

### Test runs and the dev loop

- A quiet non-blocking socket read (`EAGAIN` / `WouldBlock`, os error 35 on
  macOS) no longer ends a long run with "runtime disconnected".
- A spec busy with real network work is no longer reported as "Lost test
  session"; only transport errors count toward giving up, and budget or cancel
  exits cancel the run instead of leaving the automation lock held.
- The macOS Runner opts out of App Nap, so a hidden window or sleeping display
  no longer drops the dev session mid-run.
- Runner WebViews keep rendering and animating while the window is covered.
- `lingxia dev` replaces a stale dev broker left by another build, and a
  runtime that disconnects during a run gets a 30 s grace to reconnect instead
  of ending the session.
- File-watch reloads are deferred while a test run is active.
- `lxdev test` never leaves a run holding the session (unwritable output
  directory, IO errors, second Ctrl-C).
- Locator actions, matchers and `t.expect.poll` are bounded by the spec's
  remaining budget and retry transient page-replacement errors.
- Hooks registered from a shared helper apply to the spec file that called it.

### Runtime and shells

- `reLaunch` delivers `onUnload` to the pages it closes.
- macOS and Windows open the first window at a size fitted to the screen, save
  the frame on move, resize and quit, and remember the maximized state.
- Windows: shell chrome and WebView2 scale to the monitor DPI; installer
  shortcut names are localized from `productNames` and the exe carries product
  version info; browser downloads default to the Downloads folder.
- Desktop lxapp switcher menus offer Uninstall, and uninstalling removes the
  switcher row.
- A trusted control page (Settings, Downloads, History) has one tab identity,
  whichever way it is opened.
- Trusted control-page navigation is preserved on Windows and attested on the
  exact start callback on Android; Apple navigation keys are bound to object
  lifetimes.
- The non-Android development badge on app icons matches Android; the Harmony
  environment badge is anchored to the launcher tile corner.
