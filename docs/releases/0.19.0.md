# LingXia 0.19.0

## Breaking changes

### separate rendered from in-viewport and add forced actions

Locator visibility means rendered, not in the viewport:
toBeHidden() and not.toBeVisible() fail for content below the fold, and
page queries report the old reading as in_viewport. Assert viewport
placement with toBeInViewport() or waitFor({ state: 'inViewport' }).
click and fill take { force: true } for elements no scroll can reach,
and locators gain filter({ hasText }), first() and last().

## Writing an lxapp

### patch real JSON responses and hang requests in network routes

t.app.network.route accepts { continue: true, patchJson }
to merge-patch the real JSON response and { hang: true } to leave a
request pending until the spec ends, for loading and timeout states.

### trace t.app.network routes and scope them to the spec

Specs can fake responses for the app's Logic fetch with
t.app.network.route(pattern, handler) — fulfill, abort, or pass through —
scoped to the running spec and cleared when it ends.

## Rust native extensions

### tie an isolated profile to its run and add profile rollback

Host automation runs started with `lxdev test --isolate` can checkpoint and roll back the target lxapp's isolated data with lx.automation().lxapp().profile.checkpoint(), restore(id) and drop(id); outside an isolated run every call rejects with E_PROFILE_NOT_ISOLATED.

### make route handlers exclusive and record sent requests

t.app.network.route handlers are exactly one of fulfill
({ status?, statusText?, headers?, contentType?, delay?, body | json }),
{ abort: 'failed' }, or { continue: true }; body is a string, ArrayBuffer,
or Uint8Array and delay holds a response up to 30 s. Request records add
headers, body (text, cut to 64 KiB), and bodyTruncated.

## CLI and CI

### scale the run budget and add --shuffle and --repeat-each

lxdev test scales its default run budget with the suite
(max(300 s, 30 s per spec)) and reports "budget exhausted after N/M"
when it runs out. New --shuffle[=SEED] and --repeat-each N expose order
dependence and flakiness.

## Docs and examples

### split Logic and host-run automation roots

In app Logic, lx.automation().lxapp() is now typed as
LogicLxAppDriver, without network, nav waitUntil: 'ready', or
captureCalls, which reject there. Test programs get HostRunAutomation from
@lingxia/types/automation-test-globals; imported LxAppDriver and NavDriver
types are unchanged.

### let prod hosts switch service environments

A prod build can switch its service environment with lx.host.getServiceEnv() and lx.host.toggleServiceEnv(); the next launch uses that environment.
