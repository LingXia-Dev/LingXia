# LingXia 0.22.0

This release raises the HarmonyOS floor to 6.1.0 (API 23), gives native Rust
hosts the same autostart controls the Control app already exposes, themes the
pull-to-refresh indicator on every shell, and lets a Windows build machine
sign and upload store-ready HAPs. The rest is fixes: localized launcher names
on macOS and Windows, iOS provisioning on keychain-less CI runners, Android
force-dark and pull-to-refresh corrections, and update recovery on 32-bit
Android. Host apps rebuild against the 0.22.0 SDK and native library
together.

## Breaking changes

### HarmonyOS 6.1.0 (API 23) is required

The HarmonyOS SDK, the host template and the showcase target and require
6.1.0 (API 23), so the SDK can use API 23 interfaces directly instead of
deprecated fallbacks such as the accessibility "reduce animations" state.

- Raise `targetSdkVersion` and `compatibleSdkVersion` in
  `harmony/build-profile.json5` to `6.1.0(23)` and build with DevEco Studio or
  the Command Line Tools 6.1.0 or later.
- Devices below HarmonyOS 6.1.0 can no longer install LingXia apps.

## Writing an lxapp

- The pull-to-refresh indicator follows the host theme on every shell: it
  takes `accentColor` (else `mutedForegroundColor`) and announces refresh
  start and end to assistive technology. Mobile content pulls down with a
  spinner; desktop shows a bar along the top of the page without moving it.
  F5, Ctrl+R and ⌘R refresh a page that enables pull-down refresh.
- A page that never declared `enablePullDownRefresh` can no longer receive
  `onPullDownRefresh` on Android: an empty page path or a failed config lookup
  now leaves the gesture off, as on every other shell.
- On macOS a refresh restarted while the indicator was still lingering from
  the previous one is honoured instead of dropped, and leaving the page
  cancels the linger so a stale timer cannot end a later refresh early.
- An lxapp pinned to light on an Android phone whose system is dark no longer
  renders as a fake dark palette: the lxapp window and its WebView opt out of
  OEM force-dark, so the page and the pull-to-refresh canvas keep the colors
  the page asked for.
- A failed update on 32-bit Android now recovers: the archive decoder uses a
  window the 32-bit zstd accepts, and when a downloaded update cannot be
  applied the existing bundle opens instead of the app failing to start.
- On iOS the shared capsule buttons act on the lxapp that is current when
  tapped, not the one that was foreground when the capsule was created.

## Embedding a host app

- Rust hosts can read and set login-item autostart with
  `lingxia::app::autostart::{is_supported, is_enabled, set_enabled}`, the same
  controls `lx.host.autostart` gives the Control app. `is_enabled` reads the
  live OS registration, including changes made outside the app, and
  `set_enabled` is idempotent; the OS may still ask the user, so read
  `is_enabled` afterwards for the effective state. The host declares the
  `autostart` capability in `lingxia.yaml`; declaring it does not register
  anything by itself.
- Product launcher names follow the system language on macOS and Windows:
  `productNames` now reaches the app bundle's localized display name, the
  Windows EXE version resources and the MSIX manifest. `executableName`
  selects a build target and never a display name; omit it for a single
  executable (Windows also honours Cargo `default-run`), and an ambiguous
  build asks for an explicit selection.
- MSIX packaging keeps `en-US` as the package default regardless of how the
  other language tags sort, compiles the localized names into the main PRI,
  and no longer requires `makepri.exe`: without it every language falls back
  to `productName`, so a bare `makeappx` setup still packages.

## CLI

- `lingxia build` and `lingxia store submit` sign and provision HarmonyOS
  packages from the Windows CLI. The Windows build previously stubbed these
  out with "requires OpenSSL tooling"; OpenSSL is now vendored on every host,
  so a Windows build machine produces store-ready HAPs and can upload them to
  AppGallery.
- iOS provisioning profiles are decoded straight from their CMS envelope, so a
  CI runner without a default keychain (an overridden `HOME`) no longer fails
  with "A default keychain could not be found" on the App Store IPA path.
  `security cms -D` remains a fallback and its stderr is now part of the
  error.
- `lingxia build --platform macos` picks the executable that `Package.swift`
  declares as a product when the SwiftPM bin directory also holds build-tool
  plugin executables, instead of asking for `macos.executableName`; the
  override still wins when set.
- `scripts/release/version.sh` moves the example lxapps' `minRuntime` to the
  new major.minor line with the version bump, so the examples keep resolving
  the in-repo `@lingxia/*` packages after a release.

## Dependencies

- Dependencies flagged by Dependabot are updated.
