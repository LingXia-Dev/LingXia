# LingXia 0.20.1

This patch lets apps check draft lxapps against the dev update service without
embedded signing keys, labels built packages with their version and
env, and fixes `lingxia upgrade` for Cargo manifests it previously skipped. No
API changes; rebuild host apps against the 0.20.1 SDK and native library
together.

## Fixes

- **Draft lxapps on the dev service**: when the app talks to the dev update
  service, `draft` lxapp and plugin packages may be unsigned, even in a
  prod-env build with no trusted public keys. Host app updates and every
  other channel still require a signature in prod builds.
- **`lingxia upgrade` and Cargo**: managed LingXia crates in
  `windows/Cargo.toml` are now upgraded, so a stale pin there no longer leaves
  the project reported as behind with nothing to apply. Expanded dependency
  tables and local Cargo dependencies are upgraded too.

## CLI

- Built packages are named `<projectName>-<productVersion>[-dev].<ext>` for
  APK/AAB, HAP, `.app`, IPA, and DMG, matching the macOS update zip and the
  Windows MSIX. Rebuilding removes the previous artifact of the same type from
  `dist/<platform>/`.
- iOS builds include a Settings page that shows the app version and, on `dev`
  builds only, the environment. The labels are localized for en, zh-Hans, and
  zh-Hant.
