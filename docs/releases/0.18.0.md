# LingXia 0.18.0

## Breaking changes

### clarify JavaScript contracts and align runtime behavior

`lx.app` is now `lx.host`; `App()` still defines the lxapp.
Tasks are handles rather than thenables — `await task.result`, iterate
`task.progress` once, and `await task.cancel()` in place of `abort()`.
`canceled: boolean` becomes `status: 'ok' | 'canceled'`, with `'empty'` added
for clipboard reads, and an action sheet takes `items: [{ id, label }]` and
answers with `id`. Download and media results carry an opaque `uri` plus
`storage: 'temp' | 'userdata' | 'downloads'` and `sizeBytes` instead of
`tempFilePath` / `filePath`; a system-Downloads reference cannot be passed to
`lx.fs`. Units are spelled out — `timeoutMs`, `durationMs`,
`maxDurationSeconds`, `durationSeconds` — alongside `sdkVersion`, `ssid` /
`bssid`, and location `coordinateSystem`. `lx.surface.onContext` is
`watchContext`, `get` is `getByKey`, and only an owned tab handle exposes
`activate` / `close` / `onClose`. Replace `setData(updates, callback)` with
`setData(updates)` followed by `await page.flush()`. Upgrade the runtime and
`@lingxia/types` together.

### resolve a notification tap through the activation token

iOS local notification taps no longer read the retired `applink` payload field. Publish with `show({ target })` so the activation token can resolve the tap; an empty token still brings the product forward and reports that the target is gone.

### open pages with the navigateTo contract

A page jump is `{ kind: 'page', page, query }` or `{ kind: 'app', appId, page, query }`, the same contract as `lx.navigateTo` / `lx.navigateToApp`. `{ kind: 'route' }` is only for a host-registered location that is not a page. `{ kind: 'appLink' }` stays a real inbound HTTPS URL (`scene === 8003`).

### publish the navigation target and retire applink from notifications

`NavigationTarget` and `JsonValue` are public types. A native host declares the locations a tap may name from `HostAddon::install_navigation_routes`, and `lingxia::navigation::lxapp_page_route` takes a configured page name — not an internal path.

### resolve taps through a navigation target

`lx.app.notification.show` takes `target` instead of `applink`: `{ kind: 'appLink', url }` for the old behaviour, `{ kind: 'route', name, params }` for a location the host registered, or omit it to just bring the product forward. The old `applink` field is now a parameter error. `status` resolves `'posted'` where it used to resolve `'shown'`.

### freeze feature support per Logic context

`lx.supports` takes a feature string instead of a query object:
`lx.supports('surface.window')`, `'surface.window.fullChrome'`,
`'app.notification'`. Unknown strings return false and non-strings throw
TypeError. The answer is now fixed for the life of a Logic context — read
`SurfaceContext.aside` from `lx.surface.onContext` in place of
`{ capability: 'surface', value: 'aside' }`, and test
`lx.app.control !== undefined` in place of `{ capability: 'control' }`.
Requires `minRuntime: "0.18.0"`.

### make "painted" a value the platform returns, not an error

A native host implementing `AppRuntime::set_app_badge` / `set_tray_badge` returns `Result<bool, PlatformError>` instead of `Result<(), PlatformError>`: `Ok(false)` where there was nothing to paint on, `Err` only for a malfunction. `lx.app.setBadge` resolves `false` for a surface it could not paint — including a macOS tray the product has not shown — rather than rejecting.

### one badge call, with the surface as its argument

`lx.tray.setBadge(value)` is removed — call `lx.app.setBadge(value)`, which already marks the tray under the default `surface: 'auto'`. `lx.app.setBadge` now returns whether anything was painted and takes `{ surface: 'auto' | 'appIcon' | 'tray' }`; gate on `lx.supports({ capability: 'badge' })`, which reports `false` on Android.

### require the Control app for lx.tray

`lx.tray.setIcon/setTitle/setMenu/onClick/show/hide` are Control-app only. A guest lxapp that called one now receives a permission error; move the call into the Control app.

### publish lxapps and plugins to a named product

`lingxia publish` for an lxapp or plugin needs the product it
belongs to. Pass `--lingxia-id <id>`, or publish from a host project whose
`lingxia.yaml` sets `app.lingxiaId`.

### remove the force-update mechanism

`isForceUpdate` is gone from the `UpdateReady` event and
host-app update info, and there is no forced update any more. Offer the
update and apply it when the user confirms; a package that needs a newer
host rejects with `hostUpgradeRequired(error)` (business code 6002).

### give LxNavigator the placements lx.surface has

`LxNavigator` `target` is now `page | lxapp | url`, and
placement moves to `as`. Replace `target="self"` on a url with `as="tab"`,
drop `target="browser"` (a url opens in the system browser by default),
and drop `open-type="openUrl"`. Pages and urls can now open as
`float` / `window` and `tab` / `aside`, matching `lx.surface`.

### expose content sizeClass as compact|regular

Content `lx.surface.onContext` now reports
`sizeClass: 'compact' | 'regular'`. Former `medium` and `expanded` values
are `regular`. Shell layout automation still uses three classes.

## Writing an lxapp

### harden the store channel after review

On a store channel `apply()` resolves `{ state: 'storeOpened' }`; `update:` always requires `trustedPublicKeys`.

### store vs direct channel, prompt to open the marketplace

lx.app.checkUpdate() still returns hasUpdate on store-channel hosts; apply() opens the platform store listing. HostAppUpdateInfo.channel is 'direct' | 'store'.

### add release note for lx.app.notification

Control apps can post local banners via lx.app.notification when the host declares capabilities.notifications. The member is absent otherwise, and presence always agrees with lx.supports({ capability: 'notifications' }). Declaring the yaml flag never prompts; permission runs on requestPermission() or the first show().

### add lx.clipboard for text and image

lxapps can read and write the system clipboard via lx.clipboard (text and image). The runtime never toasts on write; a dismissed paste prompt is canceled, and a denied read rejects with E_PERMISSION_DENIED.

## Embedding a host app

### document pin ordering for automation callers

Hosts can set browser.bookmarks to false to hide bookmark controls while retaining pinned-site management and legacy bookmark lists. Automation callers can reorder mixed website and lxapp pins with lx.automation().shell.reorderPins({items}), passing every current item from shell.pins() exactly once. Trusted browser pages can restore closed website tabs with tabs.recentlyClosed and tabs.reopen({id?}); desktop users can use Cmd+Shift+T or Ctrl+Shift+T.

### add a product-drawn desktop banner

Control apps can show a product-drawn desktop banner with
lx.app.banner / lingxia::app::banner. Same id replaces; present failures
reject.

## Docs and examples

### name the stream-handle return and sync generated logic.ts

Exclusive option bags no longer accept conflicting fields. Page this.data is a deep-readonly view of the declared shape. lx.app.checkUpdate() only queries; take over the host update flow with lx.app.claimCustomUpdate().
