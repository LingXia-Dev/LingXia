# LingXia 0.24.0

A project created from a template now builds and runs with `lingxia build`
and `lingxia dev` alone: the template's build preparation and dev companion
come from the installed template, and the project tracks no generated code.
lxapp updates only move forward. A production host switched to the dev
service opens unsigned packages on every channel. Apple hosts merge their
resources into the main bundle, so re-signing no longer loses `app.json`.
Windows hosts route page lifecycle events to the right page instance. Host
apps rebuild against the 0.24.0 SDK and native library together.

## Breaking changes

### Template lifecycles run from the installed template

- `prepare` and `companion` in `lingxia-template.json` now have the same shape
  as `create`: `{ "command": "<path in the template>", "args": [...] }`. The
  command runs from the lxapp directory with `LINGXIA_TEMPLATE_ROOT` set;
  `.js`, `.mjs` and `.cjs` entries run through `node`. The `{ "run": [...] }`
  form no longer loads, and no launcher on `PATH` is needed.
- A templated project keeps one LingXia file, `.lingxia/template.json`, with
  the template `name` and the `source` to install it from. It records no
  version: builds use the installed template, and `lingxia template update`
  moves it. LingXia no longer writes or reads `.lingxia/dev-companion.json` or
  `.lingxia/build-prepare.json`; delete them and commit only `template.json`.
- An installed template still in the old shape is listed by
  `lingxia template list` as needing `lingxia template update <name>`, which
  replaces it. `lingxia template remove` also handles it.

### lxapp versions never go down

- An update installs only a strictly higher semantic version, on both channels
  (`1.10.0` is newer than `1.9.0`). On the `draft` channel the same version
  also installs when its sha256 differs; `release` compares versions only.
- A server that serves an older version no longer downgrades a device. To roll
  back, publish the old code under a higher version.
- Opening with a `targetVersion` older than the installed one fails with
  "downgrades are not supported".
- A host-bundled lxapp without an install record is compared against its own
  `lxapp.json` version rather than `0.0.1`.

## Templates

- `lingxia build` runs the template's `prepare` before dependency installation
  and the build cache lookup, so generated inputs such as a functions client
  exist on a fresh clone. `lingxia dev` runs it once when the session starts,
  then starts the `companion`, which keeps those inputs current; rebuilds on
  save never run `prepare`. Prebuilt bundles never run it.
- When the project's template is not installed, `lingxia build` and
  `lingxia dev` fail and name `lingxia template add <source>`. Nothing installs
  a template automatically.
- A template added from a local checkout is recorded in new projects by that
  checkout's `origin` URL, not its local path.
- The lxapp scaffold ignores `.lingxia/*` except `template.json`, and
  `lingxia clean` keeps that file.

## Writing an lxapp

- A production host switched to the dev service accepts unsigned lxapp and
  plugin packages on every channel, not only `draft`. Since 0.23.0 opens
  `release` by default, an ordinary open on the dev service failed with
  "prod builds require signed updates". Host self-updates and packages from the
  prod service still require signatures.
- A React page whose entry only picks a View, with each View calling
  `useLxPage()` itself, no longer fails the build with "does not forward
  Page(...) actions". The check now applies only to an entry that binds
  `actions` and passes a rewrapped object down.
- A page's Logic object is no longer garbage-collected while the page is still
  open, which could crash a session when QuickJS collected it.
- `@lingxia/test` step reports use one start time for both their trace offset
  and their duration.

## Embedding a host app

- Apple: the CLI merges the host target's SwiftPM resource bundle into the
  app's resource root (the iOS `.app` root, macOS `Contents/Resources`), and
  the runtime reads resources only from the main bundle and the SDK bundle. A
  re-sign that changes the bundle id no longer loses `app.json`, so 0.23.0's
  install-time `CFBundleName` rewrite is gone. macOS no longer ships host
  resources twice.
- Apple: a host target that declares resources but produces no resource bundle
  fails the build instead of shipping an app without assets.
- iOS: `lingxia install` checks for `devicectl` up front and reports why it
  failed instead of timing out after 30 seconds. `lingxia doctor` flags an
  active developer directory that is the Command Line Tools rather than Xcode.
- Windows: page lifecycle events are routed by page instance and session and
  delivered in order. A late hide from a replaced page no longer pauses the
  page that replaced it, and relaunching the same route keeps the new page
  shown. Activating the app no longer sends `onShow` to a page parked behind
  another.
- Windows: when a page's host window closes, other WebViews it contained are
  moved out first instead of being destroyed with it, so panels and covered
  pages no longer turn blank.

## CLI

- Building the CLI from source reuses its embedded bridge JavaScript from a
  content-hash cache in the Cargo target directory, so a fresh worktree builds
  without `npm install` when the bridge sources are unchanged, and switching
  branches no longer rebuilds it.
