# LingXia 0.25.0

`lingxia publish` now takes everything it uploads from the package itself and
runs from any directory, and `lingxia package` records its outputs in a
manifest that `publish`, `store submit` and `install` read. Building a
templated project no longer needs the template installed: the project's own
`lingxia:prepare` script generates its inputs. Apple hosts depend on the SDK
through a fixed project-local path. Desktop sidebars expand from the top and
peek open when hovering the collapsed rail. iOS native components scroll and
clip with the page. Host apps rebuild against the 0.25.0 SDK and native
library together.

## Breaking changes

### `lingxia publish <PACKAGE>`

- A host package is published with `lingxia publish <PACKAGE>`, a positional
  path to a file or a `dist/<platform>` directory, from any directory. Its
  `lingxiaId`, `productVersion` and `env` come from the packaged `app.json`,
  and its platform from the archive's layout, never its file name. An `--env`
  that differs from the package's env is an error.
- `--package-path`, `--platform` and `dist/` discovery are removed, and neither
  `publish` nor `auth login/logout` reads `lingxia.yaml`. The server comes from
  `--lingxia-server` or the default saved by
  `lingxia auth login lingxia --server`.
- An lxapp or lxplugin publish builds the project and uploads the appId,
  version and `minRuntime` of the built archive; it stops if the project
  disagrees with its own build.
- `--update-signing-key` / `LINGXIA_UPDATE_SIGNING_KEY` take the base64url
  Ed25519 seed itself. `--update-signing-key-file` and
  `LINGXIA_UPDATE_SIGNING_KEY_FILE` are removed; a file path passed as the key
  fails with "not a file path". `--help` never prints the key.

### `dist/<platform>/manifest.json`

- `lingxia package` writes `dist/<platform>/manifest.json` with the platform,
  version, env, `lingxiaId`, and each file's format, `sha256` and size. It
  replaces Windows' `-artifacts.json`.
- `lingxia publish <DIR>` uploads the recorded update payload and refuses a
  file that changed since packaging; `--dry-run` prints that path and uploads
  nothing, so CI can check signatures first. `lingxia install <DIR>` installs
  the recorded APK, IPA or HAP.
- `lingxia store submit` uploads only what the manifest lists, so run
  `lingxia package` before submitting: an artifact copied into `dist/` by hand
  is no longer picked up.

### Build preparation is the project's `lingxia:prepare` script

- `lingxia build` runs `npm run lingxia:prepare` from the lxapp's
  `package.json` before dependency installation on every source build;
  `lingxia dev` runs it once at session start. Without the script nothing runs.
- The template manifest's `prepare` lifecycle is removed. Move its command into
  the project's `lingxia:prepare` script. Building needs no installed template;
  only `lingxia dev` does, for the `companion`.

### Apple hosts declare the SDK at `../.lingxia/sdk/apple`

- `lingxia build`, `dev` and `upgrade` no longer inject the cached SDK's
  absolute path into `Package.swift`. They maintain an ignored link at
  `.lingxia/sdk/apple` pointing to the selected SDK (a junction on Windows
  without symlink rights).
- Existing iOS and macOS hosts must declare the dependency themselves, as new
  templates do:

  ```swift
  .package(name: "lingxia", path: "../.lingxia/sdk/apple"),
  // in the target's dependencies:
  .product(name: "lingxia", package: "lingxia"),
  ```

## Desktop shell

- The sidebar's expand and collapse controls moved from the footer to the top.
  On Windows a left sidebar's toggle shares the caption row; on macOS the rail
  toggle sits below the traffic lights.
- Hovering the collapsed rail's expand control for 300 ms floats the expanded
  sidebar over the workspace without moving it. It closes when the pointer
  leaves, on Esc, a click outside, or navigation inside it. Clicking the
  control pins the sidebar, and Cmd/Ctrl+\ pins or collapses it. In a compact
  window, where pinning is unavailable, the click toggles the peek.
- The sidebar toggles are redrawn as three lines with a chevron, and Windows
  names the sidebar header controls on hover.
- macOS: every host gets a standard menu bar with About, Quit, Edit and Window
  menus in the in-app display language, so ⌘Q, ⌘C/⌘V/⌘X/⌘A and ⌘M work in
  WebViews. A host that installs its own menu keeps it. The About panel shows
  the product name and version only.
- macOS: pull-to-refresh no longer slides the page over a spinner; the pull
  fills the refresh bar in place, as ⌘R and Windows already show.

## Embedding a host app

- iOS: each native component Root mounts into WebKit's own scrolling layer,
  so native views scroll, clip and stack with the surrounding HTML, and HTML
  painted above them receives touches. Roots with transforms, zoom,
  translucency or overflowing content keep the overlay. Native views stacked
  above a video stay visible.
- iOS: a host whose `app.projectName` equals its `homeAppId` no longer fails
  packaging with "Not a directory". The executable is always named
  `LingXiaAppRunner`.
- Android: a host without `splash:` keeps its starting window until the home
  page is ready instead of showing an empty Activity first, on Android 5 too.
- Android: stroked SVG tab icons fill their slot instead of rendering small
  and off-center; opening the browser no longer times out waiting for proxy
  setup; and an appearance change updates the color scheme of open web pages
  without reloading them.
- Harmony: the embedded browser opens, keeps its page when hidden, and reopens
  with working native controls; stroke-only tab icons no longer render filled.
- Windows: template lifecycle scripts run again. Node 24 rejected the `\\?\`
  paths they were given, so every `.mjs` lifecycle failed with
  `EISDIR: lstat 'C:'`.

## CLI

- `lingxia icon` sizes macOS and Windows icons on Apple's 824/1024 plate, so
  they no longer look smaller than their Dock neighbours, and art already on
  the grid is not shrunk again. Rerun `lingxia icon <AppIcon.png>
  --platform macos` to pick it up. `Contents.json` is written in a stable
  order.
- The global `--skip-skill` / `LINGXIA_SKIP_SKILL` is removed; background
  skill sync only updates an existing copy, and an auto-update no longer rolls
  the skill back to the old binary's version.
