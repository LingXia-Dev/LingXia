# LingXia 0.30.0

The Control app's `lx.shell` API is simpler: surfaces are found by what they
show instead of by runtime id, `openApp` moves a running app between the main
area and the side panel, and the Control app can set the name and icon the host
shows for it. File pickers are named `pick*` throughout and return the file's
name. Lxapp installs and data are kept apart per service env. Desktop pages
with pull-down refresh get a refresh button. Every item under Breaking changes
needs a code change; there are no aliases.

## Breaking changes

### Lxapp installs and data are kept per service env

A prod build switched to the dev service used to share installs and data with
the prod service, so a dev package could keep running after switching back and
a dev login could be sent to prod. Installs, plugin installs and lxapp data
(`userdata`, `usercache`, temp, `lx.getStorage`) are now separate per service
env, home lxapp included.

- After upgrading, every lxapp and plugin installs fresh from the bundle or
  the server.
- Data written by earlier versions is no longer read: logins and storage start
  empty.
- `lxdev` profile snapshots saved earlier must be saved again.

### File pickers are `pick*` and return the name

`lx.chooseFile` is removed, and `chooseDirectory` and `chooseMedia` are renamed.

| Before | After |
| --- | --- |
| `lx.chooseFile()` | `lx.pickFile()` for one file, `lx.pickFiles()` for several |
| `lx.chooseDirectory()` | `lx.pickDirectory()` |
| `lx.chooseMedia()` | `lx.pickMedia()`, options and result unchanged |

- `pickFile()` and `pickDirectory()` return `{ uri, name }`. `pickDirectory`'s
  `path` is now `uri`.
- `pickFiles()` returns `files: [{ uri, name }]` instead of `paths`.
- `name` is for display: it is not unique and may lack an extension.
- A picked `uri` is read-only and valid for the current session. Use
  `lx.fs.copy` to keep the file.
- On Android and on Harmony phones, `pickDirectory()` without a `defaultPath`
  inside lxapp storage rejects with `E_NOT_SUPPORTED`. Fall back to `pickFile`
  or `pickFiles`.
- On Windows, `pickMedia` with only the camera source rejects with
  `E_NOT_SUPPORTED` instead of opening a file dialog.
- In Rust, `FileService` has `pick_file` and `pick_directory`,
  `FileDialogResult.paths` is `entries: Vec<PickedPath { path, name }>`, and
  `ChosenMediaEntry` is `PickedMediaEntry`.

### `lx.getLxAppInfo()` is `lx.getAppInfo()`

The result's `appName` field is `name`, and the `LxAppInfo` type is `AppInfo`.
Replace the call and read `.name`.

### Surfaces are found by what they show, not by id

Surface handles and their `onShow`, `onHide` and `onClose` events no longer
carry `id`, and handles no longer carry `role` or `presentation`. Read
`handle.realized` for where a surface is now; it follows the surface when it
moves.

- `lx.shell.getApp(appId)` returns the handle of a running app, or `undefined`.
- `lx.shell.getDeclared(id, key?)` returns the handle of a surface declared in
  `lingxia.yaml`, or `undefined`.
- Both are for the Control app, and both return the same object the opener
  holds.
- A running lxapp has one handle. When a declaration shows an lxapp,
  `openDeclared` and `getDeclared` return that app's handle (`kind: 'app'`),
  the same object `openApp` and `getApp` return.
- `lx.shell.openApp` no longer takes `key`: an app is one surface.
- `lx.surface.getByKey` returns only the caller's own page and URL surfaces.

### `lx.shell.openApp` moves a running app; `lx.shell.reconfigure` is removed

`lx.shell.openApp(appId, options?)` no longer requires `options` or `as`.

- Without `as`, a running app keeps its place and is brought forward. A closed
  app opens in the main area.
- With `as` naming the other place, a running app moves there on macOS and
  Windows. Its Logic, page stack and WebViews are kept, and `page` and `query`
  arrive as App `onShow`. This used to reject with `E_SURFACE_CONFLICT`.
- iOS, Android and HarmonyOS reject that move with `E_NOT_SUPPORTED`.
- The home app stays in the main area: asking for `aside` rejects with
  `E_SURFACE_ROLE_LOCKED`.
- An unknown `page`, or a `channel` other than the running one, rejects before
  anything moves.
- To move a declared surface, call `lx.shell.openDeclared(id, { as, edge })`
  where you called `reconfigure`.

### `lx.shell.sidebarActions` returns promises

`replace`, `update` and `remove` return `Promise<void>` and reject on failure
instead of throwing. They still apply when called, in call order. A `try` /
`catch` around the call no longer sees a failure: `await` it or attach
`.catch`.

`sidebarActions.clear()` is removed. Call `replace([])`.

### Surface refusals have their own error codes

| Refusal | `error.code` now | Before |
| --- | --- | --- |
| Hiding a main surface, closing the root main, moving it out of main | `E_SURFACE_ROLE_LOCKED` (`data.code` `'role_locked'`) | `E_NOT_SUPPORTED` or `E_SURFACE_CONFLICT` |
| The provider capability is missing | `E_CAPABILITY_MISSING` | `E_NOT_SUPPORTED` |
| `lx.shell.openApp` fails | `E_INVALID_ARG`, `E_NOT_SUPPORTED`, `E_SURFACE_CONFLICT` or `E_INTERNAL`, by cause | always `E_NOT_FOUND` |

`data.code` is otherwise unchanged: an app taken down by the operator still
carries `maintain` or `suspended`.

## The Control app sets its own name and icon

`lx.shell.setAppDisplay({ name, icon })` changes the name and icon the host
shows for the Control app, for example to a tenant's brand. It applies to the
sidebar row, the switcher, pins and side panel tabs on macOS and Windows.

- A key set to `undefined`, `null` or `''` goes back to its default. Keys you
  leave out are unchanged.
- The name is one line of 1 to 64 characters.
- The icon is a bundled file or an `lx://` path: PNG, JPEG, WebP or SVG, at
  most 1 MiB, and at most 4096 px on a side for raster images. A network URL
  is not accepted; download the file first. SVG content is not checked.
- The choice is kept across launches, separately per service env, and removed
  on uninstall. It ranks above the registry name and `lxapp.json`.
- `lx.getAppInfo().name` keeps returning the `lxapp.json` name.

## Refresh button on desktop

A desktop has no pull gesture, so on macOS and Windows a page that declares
`enablePullDownRefresh` gets a refresh button in the navigation bar, in the
main area and in the side panel. It runs the same refresh as ⌘R, F5 and
`lx.startPullDownRefresh()`, so `onPullDownRefresh` fires.

## Fixes

- **Surface handles.** An app's handle stays usable after the app moves
  between the main area and the side panel, including by a sidebar drag. It
  used to go dead.
- **iOS tab bar.** The bar is the height of the system one and sits above the
  home indicator instead of on it, with icons spaced from its top edge like
  system tab bars.
- **macOS tabs.** With a host page such as Settings showing, clicking an
  lxapp's tab brings that lxapp forward. It used to leave the browser on
  screen or show a blank view.
- **macOS toolbar.** Back in the window toolbar goes to the app whose bar is
  showing, not to another app's tab.
- **Windows pick dialogs.** `pickFile`, `pickFiles`, `pickDirectory` and
  `pickMedia` open over the window of the calling page, reject on a dialog
  error instead of reporting a cancel, and refuse a typed name that does not
  exist.
- **Picked paths.** A picked path that does not exist rejects with
  `E_NOT_FOUND` instead of `E_INTERNAL`.
- **`readDir`.** Entries are plain objects, so `JSON.stringify` no longer
  turns each one into `null`.
