# LingXia 0.30.0

## Breaking changes

### make lx.shell.sidebarActions mutations return promises

lx.shell.sidebarActions.replace, update and remove now return Promise<void> and reject on failure instead of throwing; await them or attach .catch. sidebarActions.clear() is removed; call replace([]) instead.

### look up shell surfaces by identity instead of handle ids

Surface handles and their onShow/onHide/onClose events no longer expose id. Find a live app with lx.shell.getApp(appId) and a declared surface with lx.shell.getDeclared(id, key?), and drop key from lx.shell.openApp options. A declaration that shows an lxapp answers openDeclared and getDeclared with that app's AppSurface (kind 'app'), the same object openApp and getApp return. lx.surface.getByKey now returns only page and URL surfaces.

### let lx.shell.openApp move a live app instead of lx.shell.reconfigure

lx.shell.reconfigure is removed; use lx.shell.openDeclared(id, { as, edge }) to move a live declared surface. lx.shell.openApp(appId, options?) no longer requires options or as: omitted, a live app keeps its role and a closed one opens in main. On macOS and Windows, passing as for the other role now moves the live app (Logic, page stack and WebViews kept, page/query delivered as App onShow) instead of rejecting with E_SURFACE_CONFLICT; iOS, Android and HarmonyOS reject that move with E_NOT_SUPPORTED.

### give surface refusals their own error codes

Surface refusals now have distinct error.code values. Hiding a main surface, closing the root main, or moving it out of main rejects with E_SURFACE_ROLE_LOCKED (data.code 'role_locked'; it was E_NOT_SUPPORTED or E_SURFACE_CONFLICT). A missing provider capability rejects with E_CAPABILITY_MISSING (was E_NOT_SUPPORTED). lx.shell.openApp failures keep their category (E_INVALID_ARG, E_NOT_SUPPORTED, E_SURFACE_CONFLICT, E_INTERNAL) instead of E_NOT_FOUND. data.code is unchanged otherwise.

### rename lx.getLxAppInfo to lx.getAppInfo

lx.getLxAppInfo() is now lx.getAppInfo(), and its appName field is now name; the LxAppInfo type is now AppInfo. Replace the call and read .name.

### keep lxapp installs and data apart per service env

Lxapp installs, plugin installs and lxapp data (userdata, usercache, temp, lx.getStorage) are now kept per service env, home lxapp included, so a prod build switched to the dev service no longer shares them with the prod service. Not backward compatible: after upgrading, every lxapp and plugin installs fresh from the bundle or the server, lxapp data written by earlier versions is no longer read (logins and storage start empty), and lxdev profile snapshots saved earlier must be saved again.

### return the picked file name from pickFile, pickFiles and pickDirectory

lx.pickFile() and lx.pickDirectory() now return { uri, name } (pickDirectory's `path` is renamed `uri`), and lx.pickFiles() returns `files: [{ uri, name }]` instead of `paths`. `name` is display-only, not unique, and may lack an extension. A picked uri is read-only and valid for the current session; use lx.fs.copy to keep the file. On Android, and on Harmony phones, lx.pickDirectory() without a defaultPath inside lxapp storage rejects with E_NOT_SUPPORTED; fall back to pickFile or pickFiles. In Rust, FileDialogResult.paths is now `entries: Vec<PickedPath { path, name }>`. On Windows, lx.pickMedia with only the camera source now rejects with E_NOT_SUPPORTED instead of opening a file dialog.

### rename chooseDirectory and chooseMedia to pickDirectory and pickMedia

lx.chooseDirectory is now lx.pickDirectory and lx.chooseMedia is now lx.pickMedia; options and results are unchanged. The Rust FileService methods are pick_file and pick_directory, and the type ChosenMediaEntry is PickedMediaEntry.

### remove lx.chooseFile in favor of pickFile/pickFiles

lx.chooseFile is removed. Use lx.pickFile() for one file
(result.uri) or lx.pickFiles() for several (result.paths).

## Writing an lxapp

### add lx.shell.setAppDisplay for the name and icon the host shows

The Control app can call lx.shell.setAppDisplay({ name, icon }) to change the name and icon the host shows for it, above the registry and lxapp.json. undefined, null or '' restores a key; the choice is kept per service env and removed on uninstall. The icon must be a bundled or lx:// PNG, JPEG, WebP or SVG file of at most 1 MiB, raster images at most 4096 px on a side; SVG content is not validated.
