# LingXia 0.28.0

A project can now build against an unreleased LingXia commit or a local
checkout with `lingxia pin`. Its crates and SDKs come from a checkout in the
project's `.lingxia/`, and `lingxia upgrade` drops the pin once a release
contains it. Agents get browser automation that works the way they read a
page: `lxdev browser snapshot` outlines a page with element refs, and actions
on a ref wait until the element can take them, fill forms, read text and
console output, and take annotated screenshots. The same primitives are on
`t.automation.browser`. Vue and the `--framework` flag are gone, so a project
is React or HTML, and so is the home lxapp's process capability. iOS App Links
are signed again under a wildcard Associated Domains grant. Host apps rebuild
against the 0.28.0 SDK and native library together.

## Breaking changes

### Vue and `--framework` are removed

A project is React or HTML, decided by its page files or by `"framework"` in
`lxapp.json`.

- Port `.vue` pages to React (`.tsx`) or HTML. `"framework": "vue"` and
  `@lingxia/vue` now fail the build, with a message naming the alternatives.
- Drop `--framework` from `lingxia build`, `lingxia dev` and scripts. It only
  picked between React and Vue copies of the same pages, and is now an error.

### The process capability is removed

`capabilities.process` and the home lxapp's `Rong.spawn`, `Rong.spawnSync` and
`Rong.$` are gone, along with `lx.supports('process')`, the `@lingxia/types/process`
declarations and the `lingxia/process` cargo feature. Run local programs
from native code or a host-declared tool instead. Delete:

- `process:` under `capabilities` in `lingxia.yaml`;
- `process = ["lingxia/process", …]` from the native `Cargo.toml`;
- `process = ["host/process"]` from the Windows `Cargo.toml`.

### Browser automation targets elements by ref or CSS

`lxdev browser click`, `fill`, `type`, `press` and `scroll-to` take
`--ref <ref>` (from `lxdev browser snapshot`) or `--css <selector>`; the
selector-only forms are gone. On `t.automation.browser`, actions take
`{ ref }` or `{ css, index? }`, and `click` resolves to a result object
instead of `null`.

## Pin the LingXia source a project builds against

`lingxia pin <ref>` records a release tag, branch or commit of the official
repository or a fork in `lingxia.lock`. Commit it with the `Cargo.toml` and
`Cargo.lock` it writes.

- An official release keeps crates.io. Any other commit is checked out once
  into `.lingxia/lingxia-src`. The project's LingXia crates build from it
  through a managed `[patch.crates-io]` block, and its SDKs are built from it
  and cached in `.lingxia/source-sdk`. A re-pin moves the checkout in place,
  so the next SDK build is incremental.
- Only the crates the project's dependency graph uses are patched, and cargo
  never fetches LingXia a second time.
- In CI, cache `.lingxia/` keyed on `lingxia.lock`. In a fresh clone, run a
  `lingxia build` once before plain `cargo`.
- `lingxia pin <path>` builds a local LingXia checkout instead, without
  touching the lock, until `lingxia pin --no-local`. Every build names the
  local source, and `lingxia package` refuses it.
- A pin covers native code only. The page bridge and polyfills ship in the
  CLI, so a pinned commit whose page JS differs from the CLI's is refused at
  build.
- `lingxia upgrade` drops a pin once the new release contains the pinned
  commit, then upgrades the project as usual. A fork, or a commit not yet
  released, keeps its pin.

## Browser automation for agents

`lxdev browser snapshot` outlines a page as roles, names and states, with a
ref for every element an agent can act on. It reaches open shadow roots and
same-origin iframes, marks off-screen elements, masks passwords, and can
report only what changed since the last snapshot.

- Actions on a ref or CSS selector wait until the element is visible,
  enabled, stable and not covered, and fail with a typed reason such as
  `covered` or `stale_ref`. An action can return the snapshot diff it caused.
- Form input: `fill` (including dates, ranges and `contenteditable`), `type`
  with IME composition for non-ASCII text, `select-option`, `check` and
  `uncheck`, and `set-input-files`.
- `text` returns the page's readable content as Markdown, and `console` lists
  its log messages and uncaught errors.
- `screenshot` captures the viewport, the full page, one element, or the page
  annotated with ref marks.
- `t.automation.browser` exposes the same primitives to `@lingxia/test`
  specs.
- A product build refuses `setInputFiles` until the host registers a policy
  with `lingxia_browser::page::set_input_file_policy`. Dev sessions allow it.
- A wait that reports the new URL now means the page's document is there:
  `wait-url`, `wait --loaded` and `wait-navigation` read the document itself,
  not the WebView's URL, which moves before the new page commits.

## Fixes

- **Sidebar footer.** A value cell joins the icons before it when its
  measured minimum fits, the whole value when there is room, else truncated.
  A single icon never stands alone above a value. A value equal to its label
  shows once in the tooltip and the accessibility value. Footer tooltips open
  above the entry and stay inside the window.
- **iOS App Links.** Apple's profiles grant Associated Domains as `"*"`. The
  CLI read that as "not enabled" and signed the app without App Links. It now
  signs the requested `applinks:` domains.
- **Android App Links.** The managed block in `AndroidManifest.xml` sits one
  level inside the launcher activity. A manifest written with the old
  indentation is repaired on the next build.
- **Browser frames.** `about:blank` and `srcdoc` frames load in the in-app
  browser on Windows.
- **Windows CLI.** A debug `lingxia` no longer overflows the main-thread stack.

## Building LingXia

`cargo xtask sdk --platform <apple|android|harmony|all> --out <dir>` builds the
SDK artifacts for the release workflow, CI and pinned commits alike, and
replaces `scripts/release/sdk.sh`. It needs no bash, so Android SDKs also build
on a Windows host.
