# LingXia 0.16.0

## Breaking changes

### split host env from lxapp channel

Replace host envVersion with env (dev/prod), lx.app.envVersion
with lx.app.env, and navigator/App Link envVersion with channel
(release/preview/draft). Rename YAML environment keys to dev/prod;
use --env prod for production builds and --channel preview for testing.
Reauthenticate publish tokens under dev/prod. Draft uses a new storage
namespace. Update cloud providers to omit host-update channels. Publish
signing and runtime verification now follow dev/prod, regardless of channel.

### remove downstream authority minting

Downstream crates can no longer initialize the process namespace or provide a ProcessAuthority; process setup is owned by LingXia bootstrap and requires its live session authority.

### seal platform control authority

Native hosts and extensions must stop constructing or caching control authority and use the RuntimeInfo returned by platform bootstrap plus HostAddon hooks for trusted browser, Settings, terminal, and Logic extension integration.

### authorize control operations before argument decoding

Logic must open conditional control targets through declared fixed lx.shell entries instead of generic navigation; unauthorized malformed calls now return permission denial before argument validation.

### bind execution to live session authority

Process callers must request process in the manifest and rely on a host-issued live session grant; close, restart, or takeover revokes retained child handles and requires them to be reacquired.

### seal native automation authority

Native terminal adapters must derive automation authority from the exact RuntimeInfo returned by bootstrap; code comparing runtimes by app identity must compare lxapp_id() because RuntimeInfo equality now also checks bootstrap authority.

### require browser control protocol v3

Custom browser.webui sources and built lxapp.json files must declare controlProtocolVersion: 3; missing, V2, and unknown versions now fail configuration.

### remove host-wide Settings APIs

Replace host-wide Settings and openBuiltin("settings") calls with a static settingsDestination, resolved from native host chrome through RuntimeInfo::resolve_settings_destination().

### unify effective route inventory

Replace host_method_schema with caller-filtered host_route_schema(invocation.caller()); it reports methods and channels separately and supplies the Ready schema used for dispatch.

### require native grants for privileged resources

Remove calls to lingxia::set_automation_auto_grant; request automation, downloads, or process in the manifest and issue approved session grants from HostAddon::issue_app_resource_grants.

### migrate display language consumers

Control lxapps must replace the fixed display-language setting API with lx.app.getDisplayLanguageState(), onDisplayLanguageStateChange(), and setDisplayLanguagePreference(), using canonical BCP-47 tags or auto.

### enforce document-bound control v3

Custom BrowserControl WebUIs must rebuild with the matching RequiredV3 bridge and runtime so every frame is bound to the current document session; LegacyV2 or unbound traffic no longer reaches control routes.

### classify native route audiences

Native route authors must add a fixed RouteAudience to direct registrations and use #[lingxia::native(..., audience = "...")] whenever a route is narrower than AppSessionOnly.

## Embedding a host app

### sweep orphaned installs and staged archives on clear

`lx.app.cache` now also reports and frees lxapp install
directories and staged update archives that no record references — leaked by
best-effort cleanups that failed and never retried. Live installs, pending
updates, and anything written within the last hour are never touched, and
cookies still survive a cache clear.

### add lx.app.cache for a product-wide clear-cache control

`lx.app.cache.size()` and `lx.app.cache.clear()` back a
product-wide "clear cache" control, reporting and freeing every lxapp's
usercache, idle temp, cached runtime artwork, and the WebView's regenerable
cache. Available only to the home lxapp. `size()` excludes the WebView cache,
which `clear()` still frees, so treat it as a lower bound. Userdata, the
`lx.getStorage` store, downloads, installed packages, and cookies are never
touched.

## CLI and CI

### generate the lxapp's page names as types

Navigation now completes and checks this lxapp's own page names.
Run `lingxia dev` or `lingxia build` once and the editor offers only the pages
in your manifest; a project that has not been built keeps accepting any string.
Cast a genuinely dynamic name with `page as ConfiguredPageName`. A page of
another lxapp (`lx.navigateToApp`, `lx.shell.openApp`) is unaffected.

### describe portable automation surfaces

Mobile automation conformance now treats desktop-only drivers and unavailable VideoContext bindings as optional; callers should feature-detect those surfaces.

### inject App Links with app applink and lxapps.applink

tests inject an App Link with lx.automation().lxapps.applink({ url }).

## Docs and examples

### declare Storage.has

`lx.getStorage().has(key)` is now declared on Storage and
TypedStorage. It already answered at runtime via rong_storage 0.6.1;
callers can test key presence without get-and-compare against undefined.

### close obvious Logic typing footguns

`lx.app.cache` is present only in the Control app, same gate
as `lx.app.control`. Guests no longer have the member — write
`lx.app.cache?.size()` / `.clear()`, and treat absence as not being the
Control app rather than catching a permission error. Import automation
types from `@lingxia/types/automation`; domain subpaths such as
`@lingxia/types/app` are gone.
