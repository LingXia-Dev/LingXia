# LingXia 0.29.0

## Breaking changes

### remove the inline native island

`LxNativeRoot` and its node components (`LxVideo`, `LxNativeView`, `LxNativeCover`, `LxNativeText`, `LxNativeButton`, `<lx-native-root>`, `<lx-video>`) are removed, with no alias, along with the `registerInlineNativeComponents` / `compileInlineNative*` helpers. In WebView pages play media with plain HTML `<video>` / `<audio>`; the page CSP now allows `media-src` from any https origin, and `lingxia build` no longer rejects Web media. For native-player video (rotation, loop, autoplay, ended events) use `LxMediaSwiper` with video items.

### rename the spec() API to test()

`spec` from `@lingxia/test` is now `test`, with no alias: change `import { spec } from '@lingxia/test'` to `import { test }` and every `spec(` / `spec.skip(` / `spec.configure(` … call to `test(` / `test.skip(` / `test.configure(`. Types `SpecOptions`, `SpecBody`, `SpecApi`, `SpecRequirements`, `SpecStart` are `TestOptions`, `TestBody`, `TestApi`, `TestRequirements`, `TestStart`; `DEFAULT_SPEC_TIMEOUT_MS` is `DEFAULT_TEST_TIMEOUT_MS`.

### one side panel for lxapps and browser tabs; two aside slots

Asides group into two slots, `panel` (lxapps and browser tabs in one region) and `native` (terminal), instead of `lxapp` / `browser` / `native`; an expanded window admits two. `SurfaceLayoutAsideSlot.kind` (lx automation) is now `'panel' | 'native'`: compare with `'panel'` where tests matched `'lxapp'` or `'browser'`. Rust: `SlotKind::Lxapp` and `SlotKind::Browser` are `SlotKind::Panel`; the Windows contract's `ASIDE_LXAPP_PANEL_ID` and `ASIDE_BROWSER_PANEL_ID` are `ASIDE_PANEL_ID`. Slot APIs still accept `"lxapp"` and `"browser"` as names for the panel slot.

## Writing an lxapp

### write xfail as skipped in junit.xml, not as a pass

in junit.xml a `spec.fail` that failed as declared now shows as skipped (`<skipped type="xfail">`) instead of passed; CI dashboards count it under skipped.

## CLI and CI

### ship Windows CLI tools as x64 only

Windows CLI releases now provide x64 binaries only. Windows 11 Arm uses x64 emulation. Users of an older native Arm64 CLI should rerun the installer to switch to x64 before upgrading to a release without Arm64 assets.
