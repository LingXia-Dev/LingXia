# LingXia 0.21.0

## Breaking changes

### one observable-state API for Rust hosts

Rust hosts follow app state with one pattern: `lingxia::app::watch_foreground` / `watch_display_language` / `watch_display_language_preference` / `watch_appearance` / `watch_appearance_preference` call back with the current value and then each change, on a LingXia thread, and return a `Subscription` (drop to stop, `.detach()` to keep); `foreground_changes()` and the other `*_changes()` give an async stream of the same values. New: process foreground (`is_foreground`), appearance watchers, and on iOS and HarmonyOS the background callbacks run inside an OS grace period held until they return. BREAKING: `watch_display_language` and `watch_display_language_preference` now return a `Subscription` that must be kept or detached, fire immediately with the current value, and run on a LingXia thread instead of the thread that changed the language; `display_language()` returns `LanguageTag` instead of `String`.

## Writing an lxapp

### answer leave requests from one guard primitive

a page can hold itself against the user leaving with unsaved changes — `useLxLeaveGuard(dirty, onRequest)` in `@lingxia/react` / `@lingxia/vue`, or `holdLeaveGuard(onRequest)` in `@lingxia/bridge` / `@lingxia/html`; the handler returns whether to leave. `tabBar.items[].text` and `navigationBar.title` accept `{ "default": …, "<language tag>": … }` and follow the display language without Logic. Automation gains `nav.press('back' | 'home')`, which presses the navigation bar button, leave guard included.

## Embedding a host app

### follow the product light/dark setting

The embedded browser's chrome, status bar and built-in pages now follow the product light/dark setting, and web pages see a matching prefers-color-scheme.

### document the embedded proxy contract and allow a forced re-apply

`lingxia::embedded_browser::reapply_local_proxy()` rewrites the unchanged local proxy for a host that rebuilt its listener on the same port; confirm on a device that WebKit reconnects before relying on it. The facade documents the proxy's fail-closed, scope, idempotence and threading contract.

### set the host light/dark setting from Rust

Rust host code can read and set the product's light/dark setting with `lingxia::app::appearance()`, `appearance_preference()` and `set_appearance_preference()`. Native chrome and every lxapp without a pinned scheme follow it.

## CLI and CI

### wrap Microsoft Store packages and preserve pending drafts

`lingxia store submit --platform windows` uploads the MSIX or MSIXUPLOAD inside the ZIP archive the Store submission API expects, refuses to upload while Partner Center holds a pending submission instead of deleting it, and removes the submission it created itself when a later step fails. Packages of 4 GiB and more upload, streamed rather than held in memory.
