# LingXia 0.21.0

This release gives Rust hosts one observable-state API for foreground,
display language and appearance, lets a page hold the user against leaving
with unsaved changes and localize its tab and title text from the manifest
alone, makes the embedded browser follow the product light/dark setting and
run behind a host-managed proxy, and takes `lingxia store submit` through
production submission on HarmonyOS, iOS and Windows. Host apps rebuild
against the 0.21.0 SDK and native library together; the background-grace
entry points are new on both sides.

## Breaking changes

### one observable-state API for Rust hosts

Every run-time value in `lingxia::app` now has the same three forms: a
getter, `watch_X(listener) -> Subscription`, and `X_changes() -> Changes<T>`,
for foreground, display language, display-language preference, appearance
and appearance preference.

- A watcher is called first with the current value, then once per change,
  one call at a time on a LingXia delivery thread per area. It never runs
  inside `watch_X`, never on the platform main thread, and never with a
  LingXia lock held.
- `Subscription` is `#[must_use]`: drop it to stop, or `.detach()` to keep it
  for the life of the process.
- `Changes<T>` is a `Stream` with a cancel-safe `next()`. It yields the
  current value, then the latest value after each change, with no backlog.
- Moving to the background on iOS and HarmonyOS now holds an OS grace period
  (`beginBackgroundTask` / `requestSuspendDelay`) until every foreground
  watcher has returned.
- **Breaking:** `watch_display_language` and `watch_display_language_preference`
  return a `Subscription` that must be kept or detached, fire immediately with
  the current value, and run on a LingXia thread instead of the thread that
  changed the language. `display_language()` returns `LanguageTag` instead of
  `String`.

The native library and the platform SDK must come from the same build: the
`endBackgroundGrace` entry points were added on both sides.

## Writing an lxapp

- A page can hold itself against the user leaving with unsaved changes:
  `useLxLeaveGuard(dirty, onRequest)` in `@lingxia/react` and `@lingxia/vue`,
  or `holdLeaveGuard(onRequest)` in `@lingxia/bridge` and `@lingxia/html`.
  The handler receives the reason (`back` or `home`) and returns whether to
  leave. Every user path asks: the navigation bar back and home buttons, the
  Android and HarmonyOS system back, and the iOS and HarmonyOS edge swipe.
  Only live holders are asked and all must agree; a programmatic
  `navigateBack` is never held; the guard applies to pushed pages and clears
  when the document reloads, resets or leaves the stack.
- `tabBar.items[].text` and `navigationBar.title` accept a language map,
  `{ "default": …, "<language tag>": … }`, and follow the product display
  language without Logic. Resolution matches language, script and region as
  fields, so the `zh-Hant-TW` Apple reports reads a `zh-TW` entry. A runtime
  value from `lx.tabBar.update` or `lx.navigationBar.update` still wins until
  reset with `null`. A display-language change repaints the navigation bar as
  well as the tab bar. CLI validation accepts the map form.
- Automation gains `nav.press('back' | 'home')`, which presses the navigation
  bar button the way a user does, leave guard included. It replaces
  `nav.back({ user: true })`.
- `chooseMedia` reports an empty native selection as a cancellation,
  matching the lxapp picker.

## Embedding a host app

- The embedded browser's chrome, status bar and built-in pages (New Tab,
  Settings, Downloads, History, Bookmarks) follow the product light/dark
  setting on iOS, Android and HarmonyOS, and switch while the browser is
  open. Web content sees a matching `prefers-color-scheme`; a site without a
  dark style is never force-darkened.
- Rust host code can read and set the product's light/dark setting with
  `lingxia::app::appearance()`, `appearance_preference()` and
  `set_appearance_preference()`. Native chrome and every lxapp without a
  pinned scheme follow it.
- A host can run the browser behind an app-local HTTP proxy, or explicitly
  on the system network, through the `lingxia::embedded_browser` facade, and
  owns the browser's download controls. A required proxy keeps cookies and
  request headers, never falls back to the destination, and is selected again
  on retry and resume; a transport change pauses active downloads, and a
  download blocked by a disconnected proxy is reported as an ordinary failed
  download. `reapply_local_proxy()` rewrites the unchanged proxy for a host
  that rebuilt its listener on the same port; confirm on a device that WebKit
  reconnects before relying on it. The facade documents the proxy's
  fail-closed, scope, idempotence and threading contract; on Android and
  HarmonyOS the override is app-wide.
- The proxy HTTP client is linked only for browser hosts (the
  `lingxia-transfer` `http-proxy` feature), and `browser.platforms` now gates
  the proxy feature, generated surfaces, macOS validation and webui bundling.
- The mobile browser's New Tab, Downloads and Settings controls open their
  pages through the live home-app session and sealed native browser
  authority on iOS, Android and HarmonyOS, and the overflow menu labels follow
  the product display language on all three.
- iPhone browser WebViews send a Safari-style user agent, so sites serve
  their web UI instead of redirecting to an external browser. iPad keeps the
  WKWebView default.
- Native `chooseMedia` results are typed and distinguish cancellation from
  failure; the iOS picker's buttons use the host localization and its cancel
  control has an accessibility label.

## CLI

- `lingxia new .` creates the project in the current directory, named after
  it. A directory holding only `.git`, `.gitignore`, `.gitattributes`,
  `README*` and `LICENSE*` is accepted; existing files are kept, an existing
  `.gitignore` gains the generated lines it lacks, and an existing repository
  is left without an initial commit.
- `lingxia store submit` now completes production submission on HarmonyOS,
  iOS and Windows:
  - HarmonyOS release packages are signed by the Rust signer, including the
    outer `.app` AppGallery used to reject with error 991. `--track apptest
    --wait` uploads to the test area, waits for parsing, then creates and
    binds an invitation-test draft; `--test-version-id` reuses one, and JSON
    output returns both ids.
  - iOS `Info.plist` is populated from the active SDK and Xcode, `altool`'s
    JSON result is parsed and explicit success required, so a validation
    failure can no longer be reported as a successful upload. Uploads feed
    both Distribution and TestFlight, and a missing App Store Connect record
    is explained.
  - Windows uploads the MSIX or MSIXUPLOAD inside the ZIP archive the Store
    submission API expects, refuses to upload while Partner Center holds a
    pending submission instead of deleting it, and removes the submission it
    created itself when a later step fails. Packages of 4 GiB and more are
    streamed from disk.
