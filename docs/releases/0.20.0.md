# LingXia 0.20.0

This release identifies every page by its instance across the platform
contract, fixes a run of pull-to-refresh and WebView-readiness bugs on each
shell, lets a View build take custom Vite plugins, and teaches the CLI to use
a SOCKS proxy. Host apps rebuild against the 0.20.0 SDK and native library
together; a mismatched pair fails to link.

## Breaking changes

### identify pages by instance on every platform

Pages are identified by instance (the webview tag) across the platform
contract, so two pages of the same route are never confused.

- Swift hosts: `LxAppNavigateRequest` and `LxAppControllerEvent.didNavigate`
  gain `pageInstanceId`; iOS `LxAppViewController.navigate`, `openLxApp` and
  `handleNavigation` take the page instance; `LxApp.startPullDownRefresh` /
  `stopPullDownRefresh` take a webtag.
- Kotlin hosts: `LxApp.open(appId, path, sessionId)` becomes
  `LxApp.show(appId, webtag, sessionId)` (the host entry `LxApp.open(appId,
  path)` stays); `LxApp.navigate` and `LxAppActivity.openLxApp` drop their
  path argument; `LxAppPullToRefresh.startPullDownRefresh` /
  `stopPullDownRefresh` take a webtag.
- Rust platform implementors: `AppRuntime::show_lxapp` takes a `ShowLxApp`
  request and `navigate` takes `(appid, webtag, animation)`; `UIUpdate` loses
  its appearance and launch-splash methods to the new `Appearance` and
  `LaunchFace` traits; `PullToRefresh` takes a webtag; `SurfaceRequest`
  carries `SurfaceContent::Page { webtag }` or `SurfaceContent::Url { url }`
  and `owner_session_id` instead of `path`, `session_id` and
  `page_instance_id`.

The native library and the platform SDK must come from the same build: JNI
and FFI names changed on both sides.

## Writing an lxapp

- A View build accepts Vite plugins through `view.plugins` in
  `lxapp.config.ts`, such as `@vitejs/plugin-legacy`; plugin output survives
  packaging, and hosts whose bundles use View plugins still receive the ES5
  polyfills. Configuration import errors now fail the build.
- A Logic restart that loses its worker replaces the session instead of
  leaving a dead one behind; retired sessions are cleaned up when a restart
  fails.

## Embedding a host app

- Pull-to-refresh on HarmonyOS has the same resistance, trigger and hold as
  the other shells, its safety timer is cancelled with the refresh, and a
  programmatic refresh is reported once. iOS gives back the refresh inset
  whenever a refresh ends.
- Apple, Windows and Android wait for a page's WebView to be ready instead of
  polling for it; Android reports a WebView creation that threw, so the page
  no longer waits forever, and presents the page the runtime names once its
  WebView exists.
- Android keeps the classes and members the runtime reaches through JNI
  under R8, and the update dialog answers its first click.
- Modals raised before the first screen exists are shown once it does.
- HarmonyOS holds a page eval's answer until `LingXiaProxy` exists, keeps the
  screen on during automation runs, draws the navigation bar's home icon as an
  outline, and reports unschedulable notifications as `E_NOT_SUPPORTED`.
  HarmonyOS launches again on rong_arkjs 0.6.2.
- The macOS Runner opens where the last window closed and stays where the
  user moved it.

## CLI

- `lingxia` picks the HTTPS proxy before `ALL_PROXY` and speaks SOCKS.
