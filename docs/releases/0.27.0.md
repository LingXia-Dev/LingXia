# LingXia 0.27.0

A guest lxapp, one published on its own rather than as the Control app, can
now post its own notifications and desktop banners and come forward when the
person acts on them, with `lx.surface.bringToFront`. On macOS and Windows,
dragging an aside tab onto the sidebar promotes it to a main without
restarting it. A newer CLI builds an older project as long as its line is in
the support window, and `LINGXIA_ALLOW_SKEW` is gone. Footer sidebar actions
are icon buttons, with an optional `value` for the brand, store or account the
person is working in. Host and lxapp package downloads that take longer than a
minute now finish, and resume if dropped, and an always-on device can
re-check for updates on an interval. `lxdev network devtools` shows a
session's live traffic in Chrome DevTools, and `lxdev test --changed` runs
only the specs a change can affect. Host apps rebuild against the 0.27.0 SDK
and native library together.

## Breaking changes

### `LINGXIA_ALLOW_SKEW` is removed

- A CLI builds a project whose line is in `[0.25, CLI line]` without an
  environment variable. A host's SDK pins must agree and be in that window,
  and no embedded lxapp may have a higher `minRuntime` than the host.
- Each lxapp's `@lingxia/*` packages must be on its `minRuntime` line.
  Packages newer than `minRuntime` now fail the build; the error names the
  `minRuntime` to raise to.
- A Runner is accepted when it speaks a dev protocol the CLI supports, so a
  checkout CLI no longer rejects a release Runner of the same version.
- `LINGXIA_SKIP_COMPAT=1` turns the project, Runner and `lxdev` session
  pre-checks into warnings, for when a check misreads a project. The
  dev-session handshake still refuses an incompatible session.

### Reopening a live lxapp delivers `page` and `query`

`lx.shell.openApp` on an lxapp already open in that role used to only reveal
it and drop `page`/`query`. It now keeps the page stack and fires App `onShow`
with reason `switch_back` and the new path and query, as a re-entering link
does; route from the query there. An `openApp` with neither `page` nor `query`
is still a plain reveal. A notification or menu `app` target naming an lxapp
docked as an aside now reopens it in place instead of failing with "no longer
available".

### Footer sidebar actions draw icons, not `label`

A footer action is an icon button; `label` is its tooltip and accessibility
name and is never drawn. An action that shows a changing fact (current brand,
store, account) moves that text to the new `value` field and keeps a stable
`label` such as "Brand"; the value is drawn beside the icon on a footer row of
its own. Give icon-only actions distinct icons.

```ts
lx.shell.sidebarActions.replace([
  { id: 'agent', placement: 'footer', icon: 'public/agent.png', label: 'Agent', onActivate },
  { id: 'brand', placement: 'footer', icon: logo, label: 'Brand', value: brand.shortName, onActivate },
]);
lx.shell.sidebarActions.update('brand', { value: brand?.shortName }); // undefined clears
```

- `value` is footer-only: a header `value` is a type error and a runtime
  `E_INVALID_ARG`.
- At most two footer actions may carry a value; `update` validates the whole
  patched set.
- `update` sets every key the patch carries, so `{ value: undefined }`, `null`
  or `''` clears the value.

### `lxdev test` subcommands, and `spec` called directly

- `lxdev test --list`, `--list-presets` and `--print-args` are now
  `lxdev test list`, `lxdev test presets` and `lxdev test args`.
- A bare `lxdev test --cancel-active` is now `lxdev test cancel`;
  `--cancel-active` cancels the stuck run, then runs.
- `--pretty` needs `--format json`.
- Specs must call `spec` directly under that name. Replace
  `const s = cond ? spec.skip : spec` with
  `spec(title, { skip: cond ? 'why' : undefined }, body)` or
  `spec.configure({ skip })`, and `import { spec as x }` with
  `import { spec }`.

## Guest lxapps get attention for themselves

`lx.host.notification`, `lx.host.banner` (desktop) and the new
`lx.surface.bringToFront` are available to every lxapp. For a guest, the
effect is scoped by its session, never by the payload:

- **Ids are its own.** A guest cannot replace, cancel or dismiss another
  app's notification or banner, and its `cancelAll` clears only its own.
  The Control app's ids are unchanged.
- **A notification opens only the guest itself**: `{ kind: 'app' }` with its
  own appId or none. Other targets reject with `E_PERMISSION_DENIED`.
- **Limits:** at most 32 untapped notifications, and one OS permission
  prompt per launch, only while the guest is on screen. A prompt refused by
  that rule rejects with `E_PERMISSION_DENIED`.
- **Banners name the guest.** macOS and Windows cards show the lxapp's icon
  and name, a guest holds at most three banners showing or waiting, each
  closes within 60s, and the product's banners go ahead of every guest's.
- **`lx.surface.bringToFront({ page?, query? })`** does what a tap on the
  guest's own notification does: a docked aside comes back in place and App
  `onShow` gets `switch_back` with the page and query. A guest may call it
  once, within 10 seconds of the person picking an action on its banner. The
  Control app may call it any time.

Host code that builds a `DesktopBannerShow` keeps compiling; a guest source
goes through `banner_enqueue_from`.

## Desktop asides

- **Drag an aside tab onto the sidebar** to promote it to a main, on macOS and
  Windows. An lxapp keeps its Logic, page stack and WebViews, and stays the
  main as it navigates; a URL tab
  becomes a main-browser tab with the same tab id and document, and records
  history from then on. Clicking Pin on a live aside promotes it the same way
  instead of relaunching it. URL-callback and ephemeral tabs stay with their
  opener and cannot be dragged.
- **Aside chrome is restyled.** An lxapp aside's active tab is a centred chip
  and the separator under it stays whole; the docked browser's tab strip is
  unchanged. The aside tabBar draws as page tabs with an underline, honours
  `tabBar.style` colours, and follows the lxapp's light/dark switch.
- An lxapp the registry has no icon for shows the host's icon on macOS, as on
  Windows, rather than the LingXia mark.

## Sidebar switcher

- Hovering a switcher row shows a vertical `⋮`; the `⋮`, close and disclosure
  controls share a circular hover. On Windows the hover now appears when the
  pointer moves onto `⋮`, and the disclosure uses thin vector chevrons.
- Windows: shell context menus (switcher rows, browser tabs, pins, terminal)
  follow the product's light/dark scheme instead of always painting light.
  High contrast is left to the OS.
- macOS: the close button's hover is visible on a dark sidebar.

## Updates and package downloads

- `update.checkInterval` in lingxia.yaml (such as `6h`, at least `15m`)
  re-checks the host app and the home lxapp after each interval, also after
  a failed check. Omit it to keep checking once per process. Meant for
  always-on devices such as signage.

- Host and lxapp packages that take longer than a minute no longer fail
  mid-transfer. Downloads have a 20s connect timeout and a 60 min ceiling,
  resume from `.part`, and retry twice with backoff on network errors, 408,
  429 and 5xx.
- A download whose open is cancelled stops instead of running on in the
  background.
- Host update progress no longer overshoots when a server ignores `Range`.

## Dev tools

- **`lxdev test --changed`** runs only the specs a change can affect: those
  whose spec files import a changed file or name a page whose files changed,
  and prints why. `--changed-since main` compares with the merge base of
  `main`. Project-wide files and files nothing ties to a spec run
  everything. `lxdev test list --changed` shows the selection.
- `lxdev test list --offline` reads specs from every module the entries
  import, not only the entry files.
- `lxdev mock all|none` refuses a switch before either half changes, and
  `mock use` no longer waits 4s for a first request.

- **`lxdev network devtools`** shows the session's live traffic in Chrome
  DevTools' Network panel until Ctrl-C or the session ends. Redirects,
  event-stream frames and timings show as for a browser page, and bodies load
  on demand. It runs Chrome (else Edge) in its own profile under
  `~/.lingxia/devtools-browser`. macOS and Windows.
- **`lxdev network capture stop` picks the format from the file name**:
  `stop r.json` writes the request JSON, `stop r.har` writes HAR 1.2, and
  `stop r.json r.har` writes both. `--har FILE` still works but is
  deprecated.
- Captured event-stream frames carry `t`, when the frame's last byte arrived
  in ms since the request started (unencoded streams only). HAR carries these
  as `_lingxia.eventTimes`.
- A slow dev-session request, such as an `eval` that awaits, no longer holds
  up logs, companion replies and heartbeats.
- The DEV mark stays above `lx.surface` windows and floats on every platform.
- Runner: the toolbar gear explains how to open the Web Inspector from
  Safari's Develop menu, with an Open Safari button. It did nothing visible
  before.
- `lingxia::dev` (feature `devtool`) keeps what a host calls: dev bundles,
  the dev session, the simulated device and applink injection. The devtool
  command implementations (page query, input, eval, screenshot, navigation)
  moved into `lingxia-control-runtime` and are no longer exported.

## Other fixes

- Windows: choosing an appearance no longer reports a save error when a
  WebView is slow to apply it.
- Windows: a tap-outside float closes only on a press in its owner, not when
  the owner takes activation back after the float shows.
- A page that was open but hidden (covered by a browser tab, its window
  inactive, or below the top of the stack) when Logic cold-restarted gets
  `onLoad` again, and `onShow`/`onReady` when it is next shown. Before, it
  never readied. `lxdev lxapp restart` no longer waits 15s for such a page.
- Runner: a simulated phone or tablet frame on macOS pull-to-refreshes the
  way iOS does.
- `rong_core` 0.6.3: an explicit `undefined` is treated as an omitted
  optional argument.
